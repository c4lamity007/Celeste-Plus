# Focused visual QA

For the image-glow trajectory and ambient additions, use `module_qa.py check --module Trajectories --module "Ambient Effects" --suite ambient-vfx --java-home <JDK21>`.
This builds once, then tests trajectory core/stamp budgets and actual materials, folded falling-leaf geometry/shading,
all three sky-line patterns, and existing atmosphere math. In the GUI choose Ambient Effects → Edit effects → + Add → Falling Leaves
and/or Sky Pattern → Light Rails. Trajectories uses its existing Glow slider: zero keeps the core and suppresses image stamps.
The halo reuses the cached soft PNG, with up to 64 camera-facing arc-length stamps and normalized overlap brightness.
Leaves remain world-cell anchored, with invisible recycling; sky rails keep their angular anchors fixed while their light travels.
All contact sheets are offscreen GPU fixtures, not proof of game FPS, renderer integration, or a published release.

For Trajectories, use `module_qa.py check --module Trajectories --suite trajectories --java-home <JDK21>`.
This builds incrementally and runs `run-trajectories.ps1`: production ribbon/budget/fade geometry tests with
value-only vector/render-record adapters, then real trajectory/impact GLSL GPU tests (static material,
segment seams, Glow=0, themes, zero opacity, preserved depth). The shader preview is a posed offscreen
fixture, not Minecraft gameplay. Bow/pearl hand selection, real surface placement, camera movement,
disable/reset and the edited build's identity still need a local-world check through the normal launcher.

For Custom Sky and Custom Fog, run `module_qa.py check --module "Custom Sky" --module "Custom Fog" --suite fog-compatibility --java-home <JDK21>`. This includes an incremental build, actual sky/fog GLSL checks, native/Sodium compatibility fixtures, and shader-fog policy/lifecycle checks. Sky and shader-fog presets are Aurora, Nebula, Sunset, Abyss, and Black Hole; `Match Sky` selects the active sky's palette. Native fog remains a separate rendering option.

Nebula's three translucent dust bands have actual radial gaps and asymmetric material that orbits within a fixed ring plane. Black Hole uses an analytic shadow, accretion disk, and lensing-inspired arcs, not a physical gravity simulation. Both effects remain in the existing sky draw; no new mesh, texture, particle system, or ray-marching pass is added. Detail is filtered by pixel footprint, and costly celestial material work is restricted to its angular bounds. Offscreen GPU previews and isolated draw timings do not establish in-game appearance or FPS on other systems. Actual runtime enable/disable, loaded-build identity, camera motion, and local-world behavior still need game verification.

`run-celestial-shader.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` runs the focused Nebula/Black Hole material checks and creates a side-by-side PNG plus a five-second animated GIF from the production shaders. It accepts `-Width` (default 576) and an optional `-BaselineJar` containing the previous sky shader for an isolated old/new GPU draw-time comparison. No recorded gameplay, post-production glow, or downloaded artwork is substituted.

For Player ESP, Chams, or the client-estimated Target HUD, run `module_qa.py check --module "Player ESP" --module Chams --module "Target HUD" --suite player-visuals --java-home <JDK21>`. This records one incremental build, the existing world-effect checks, real chams/prism GPU tests, unified-volume GPU checks and the pure local-damage regression checks in a single compact report. The unified-volume step runs after prism and before local damage. New shader-only changes should use this suite, not just the older `visuals` suite.

The chams/prism/unified-volume PNGs are offscreen GPU fixtures, not Minecraft screenshots. The runtime step still needs the tested client loaded in-game. Local target health is an estimate from a 20-HP baseline and local outgoing melee attacks; it does not confirm accepted hits, healing, absorption, other players' damage or server-specific rules.

For the combined crystal/anchor and visual changes, use `module_qa.py check --module "Auto Crystal Aura" --module "Anchor Aura" --module "Block Highlight" --suite crystal-visuals --java-home <JDK21>`. This runs one incremental build, every `player-visuals` check in its existing order, then `run-block-highlight.ps1` and `check_auras.ps1`. A failing check stops the remaining plan; an all-green plan records `checks-passed` with runtime still pending. Both extended suites require an explicit JDK 21 path. No suite publishes the client, changes authentication, or installs into a Minecraft instance.

`run-block-highlight.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` runs the production shape helper and the actual volume/composite shaders. Pure tests cover cube/top-bottom slab/straight stairs, overlapping and redundant cuboids, outward union boundaries, deterministic voxel-union area/volume checks, tiny terrain-depth offsets, exact 192-face all-or-nothing budgets, translation/tint, and invalid-input/allocation caps. The GPU test renders production cube/slab/stair meshes against copied foreground/background depth, proves visible versus hidden coverage with a no-copy negative control, checks one-alpha compositing and face order, and compares the main scene depth bit-for-bit before/after. Reversed scene depth and empty following frames check stale-output cleanup. It accepts optional `-Tile 321` (default 320) and `-DependencyCache`; JDK 21, the eight cached LWJGL 3.3.3 Java/Windows-native jars and the selected project's exact merged Minecraft 1.21.11 jar are required. No dependencies are downloaded. Unique classes and `compile.log`, `shape.log`, and `depth.log` stay under `OutputRoot`; stdout contains compact summaries. It emits no screenshot and does not execute `BlockHighlightFeature` or the live Minecraft renderer adapter: crosshair selection, enable/disable/world transitions, unsupported depth-override handling, actual game appearance and loaded-build identity still need in-game QA.

`check_auras.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` compiles and executes the production pure `AuraRules` helper with `AuraRulesCheck`. This is deterministic rule regression only, not evidence of server-accepted placement/charge/detonation, outgoing packet timing, silent switching/rotation behavior, or live crystal/anchor effectiveness. Use an authorized local world and the normal launcher flow for those observations; retain authentication and identify the loaded build before reporting a runtime pass.

Run `run-visuals.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -Suite Animation|Gpu|All`.

`Animation` is the fast default. It directly compiles the selected project's pure animation and water-mesh helpers, checking animation math, pause/resume timing, takeoff predicates, raised geometry, exact ring seams, falling-wave timing, and event/quad budgets. It needs JDK 21 only, with no Minecraft classpath.

`Gpu` compiles and renders seven actual shaders using a hidden OpenGL context, their project textures, and the selected project's exact Minecraft 1.21.11 includes. It checks finite bounded floating-point output, appropriate surface boundaries, zero-opacity input, fractional-frame animation, and unchanged depth. Water's joined U edges and visible foam crest intentionally do not fade out; its base does. Volume is a closed surface and never fades at individual quad edges. It needs the local LWJGL 3.3.3 cache and working graphics access; no dependencies are downloaded. The contact sheet is a GPU preview, never an in-game screenshot. Runtime integration is outside these tests.

`run-water-showcase.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` renders the actual `WaterJumpMesh` and water/splash shaders into rising and falling 3D test scenes. The neutral floor is a fixture; neither PNG is Minecraft. It does not add post-production glow or alter any texture.

`run-volume-showcase.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` renders the production `SolidVisualMesh` with the actual volume shader. Four independent fixtures show Orbit, Helix, floating loot gems and a trajectory/landing marker. The left column uses the Celeste palette, right uses Ice. Cached Minecraft grass/dirt/stone textures and the base default Steve skin provide a recognizable context; they are read directly from the selected merged jar without downloads or asset modification. Player poses, terrain placement, daylight background and projectile arc are test fixtures, not recorded gameplay or Minecraft lighting validation. The `Animation`/`All` suite also checks the pure tube/gem geometry for finite coordinates, continuity, closed seams, invalid inputs and bounded complete meshes under constrained budgets.

`run-unified-volume.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` compiles the actual `SolidVisualMesh` and `VolumeSurfaceMesh` helpers with the GPU harness. It checks unified transparency with intersecting tube loops and a parallel-overlap fixture: the nearest visible surface's input alpha is preserved once across overlaps, with input alphas 0, 0.15, 0.35, 0.70, 0.90 and 1. It also checks draw order, depth, empty output, animation and planar diagonals. The direct GPU render `unified-volume-comparison.png` compares per-face blending with the unified result at alpha 0.35 on a transparent background; this test value does not change module defaults or impose a fixed opacity. The separate volume showcase produces `volume-showcase.png` and `volume-showcase-later.png` with ordinary per-feature/fade alphas and posed 3D fixtures on a checker floor. These are actual offscreen renders with no image postprocessing, not in-game screenshots or evidence that the edited client is loaded.

Target previews use the production `TargetAuraShape` paths, with body-relative contouring and unchanged side radius/tube thickness. `Animation`/`All` also tests body-yaw wrapping, frame interpolation, bounded sway, player/non-player paths and complete mesh budgets. This does not prove runtime target tracking or mounted-vehicle torso alignment.

The animated world materials use framebuffer-space motion inside their existing geometry/masks, so their pattern does not stick to moving mesh UVs. GPU checks compare moved geometry and framebuffer resolutions while preserving static coverage and opacity, and verify fractional-time RGB changes. The volume material retains broad enchantment currents and selected-palette shading without colored plastic gloss; its neutral-theme regression remains in place. The private-depth resolve still applies input opacity once. Target bands have square four-sided cross-sections (160 full-detail faces across either pair), with the same path, width/height and spinning helix. Supporting floor glows are tighter; opacity defaults and effect settings are unchanged.

The unified-volume runner accepts optional `-Tile 321` for odd-resolution checks (default 320), `-JdkHome` and `-DependencyCache`. It uses only cached JDK 21, LWJGL 3.3.3 Windows jars and the selected project's exact Minecraft 1.21.11 includes; it never downloads dependencies or deploys the client. Isolated compiled classes, `compile.log`, `run.log` and the comparison PNG stay beneath `OutputRoot`, with compact summaries on stdout.

The runner accepts `-JdkHome`, `-DependencyCache`, and optional `-Tile 321` for an odd-resolution GPU run. Without `-JdkHome`, it checks JAVA_HOME, the cached Temurin 21 installation, then PATH, accepting only JDK 21. ProjectRoot and OutputRoot are required. Sources/textures always come from ProjectRoot; there is no staging or older-project fallback. Classes, logs, and previews are written beneath OutputRoot. Detailed output stays in log files; stdout contains compact pass/fail summaries.

## Multiple ambient effects

Open **Ambient Effects → Edit effects**. Add a style, select it to adjust Density and Size, and use its minus button to remove it. Up to six different styles can run together; removing a style keeps its values for later. Sky Lines keeps its shared settings on the module card. Existing single-style configs migrate on load/import, and an explicitly empty new config stays empty.

Run `run-ambient-layers-ui.ps1 -JavaHome <JDK21> -Output <artifacts>` for editor input/layout and actual ModuleManager load/import/export/save fixtures. Run `run-ambient-layers.ps1 -ProjectRoot <project> -OutputRoot <artifacts> -JdkHome <JDK21>` for mixed geometry, state cleanup, work limits and GPU checks. These fixtures do not establish Minecraft appearance or FPS.
